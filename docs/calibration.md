# 実機キャリブレーション（地図色・陰影規則の測定）

BMAP の地図色と陰影規則は Java 版の値から始まっています。このページは、それを **Bedrock が実際に描いた地図** で
確かめ、測った値に置き換える方法をまとめたものです。BMAP はワールドに書き込みません。地図の読み取りは、
ワールドの `db` フォルダを一時フォルダにコピーし、そのコピーを読むだけです。

## 仕組み

1. BMAP がテストパッド（`.mcstructure`）と、測る位置を記録した `pad.json` を出力します。
2. ゲームでパッドを置き、縮尺 0 の地図を作ってパッドを描かせ、ゲームを終了して地図を保存させます。
3. BMAP がワールドの LevelDB（の一時コピー）から `map_<ID>` を読み、`colors`（128 × 128 の RGBA）を取り出します。
4. `pad.json` の位置と照らし合わせて、測定点ごとの実際の色を BMAP の予測と比べます。
   - 地図の位置（`xCenter`・`zCenter`）からパッドに対応する地図を選びます（位置が分からなければ、予測に最も近い地図）。
   - 地図の画像が回転・反転して保存されていても、8 通りの向きを試して合わせます。
   - 描かれていないピクセル（透明）は使いません。

## テストパッド

### 陰影テストパッド（地図 1 枚）

8 本の帯（各 16 行）× 16 本（各 8 列）の帯で構成されています。

| 帯 | 内容 |
|---|---|
| 1・5 | 通常のブロック（ライム・白・黒・赤のコンクリート）× 段差 1・2・3・4 |
| 2・6 | カーペット（同じ 4 色、支えブロックの上）× 段差 1〜4 |
| 3・7 | ハーフブロック（花崗岩・砂岩・シラカバ・エンドストーンレンガ）× 段差 1〜4 |
| 4・8 | 対照実験: 東西だけの段差 1〜4（通常のままのはず）、平らな 4 種、4 行ごとに北が空の列、草・オーク・ジャングル・シラカバの葉（バイオームの色） |

各帯の行の高さは 0, 0, +d, +d, 0, 0, +d, +d … なので、1 本の帯で +d・−d・0 を同時に測れます。
5〜8 本目は 1〜4 本目の繰り返しで、結果がばらつかないかを確かめます。

測定結果:

- 段差 −4〜+4 ごとの明るさ（同じ帯の平らな部分を 1.000 とした比）
- 明るくなる・暗くなる **最小の段差**（1 なのか 2 なのか）
- 段差の大きさで明るさが変わるか（段階的な陰影）
- 通常色 ÷ 基本色（Java 版は 220/255 = 0.863）、明 ÷ 通常、暗 ÷ 通常 → 陰影の倍率
- 東西だけの段差・平らな部分が通常色のままか、カーペット・ハーフブロックが同じ規則か

測定結果は、外部実装から集めた **候補モデル**（Java 段差 1、段差 2（gd-codes・Nukkit）、gd-codes の丸め、
偶奇で交互になるモデル、PowerNukkitX の段階的モデル、測定から推定した非対称モデル）すべてと照合します。
評価は、明・通常・暗の分類一致率（全体／検証用データ）、RGB の完全一致率、平均絶対誤差、最大誤差です。
パッドの後半（帯 5〜8）は段差の推定に使わず、検証用に残しています。最も一致したモデルが選ばれます
（詳しくは [bedrock-research.md](bedrock-research.md)）。

「結果を色プロファイルとして保存」で、測った倍率と段差を持つ新しい色プロファイルを作ります
（状態は「実機確認済み」、ゲームのバージョンと地図の ID を記録）。

### 色テストパッド（地図 1 枚）

全 323 ブロックを 4 × 8 の見本で並べます。見本の行の高さは 0, 0, 0, +s, +s, 0, 0, 0 で、
1・2・6・7 行目が通常、3 行目が明、5 行目が暗の色です（s は「色パッドの段差」。陰影テストパッドで段差が 2 と分かったら 2 にします）。
ブロックごとに 3 段階の色を読み取り、ばらつきの大きいもの（バイオーム・影・位置ずれ）は使いません。
保存すると、測ったブロックだけが「実機確認済み」になり、残りは推定値のままです。

## 手順

1. マップ設定 →「実機キャリブレーション（読み取り専用）」→「陰影テストパッドを出力」（または色テストパッド）。
   その他 → 建築位置で地図の範囲に合わせた座標を設定しておくと、`pad.json` に位置が入り、地図を自動で選べます。
2. 出力フォルダの `手順.txt` に従って、クリエイティブワールド（またはそのコピー）にパッドを読み込みます。
   支え行（北西の角）を指定の座標に合わせ、地図の範囲とぴったり重ねます。
3. 白紙の地図（縮尺 0、拡大しない）を持ってパッドの上を歩き、全体を描かせます。
4. ワールドを出てゲームを終了します（地図のデータを確実に保存させるため）。
5. BMAP でワールドと `pad.json` を選び、「地図を読み取って比較」。
   プレビューの「キャリブレーション」に、左: ゲームの地図、中: 予測、右: 差 が表示されます。
6. 「結果を色プロファイルとして保存」。

コマンドラインでも同じことができます:

```bash
BMAP.Cli pad shading out --origin 0,0,64
BMAP.Cli calibrate "<ワールドのフォルダ>" out/BMAP_shading_pad/pad.json --out result
BMAP.Cli mapcheck "<ワールドのフォルダ>"...
```

`mapcheck` は、どのワールドの地図でも（何が描かれていても）全ピクセルが「基本色 × 倍率」になっているかを調べます。

## 色の状態（プロファイル）

| 状態 | 意味 |
|---|---|
| 実機確認済み（Verified） | 対象のバージョンで、ゲームが描いた地図から読み取った値 |
| API 由来（API-derived） | Bedrock のデータ定義（ビヘイビアパックの `minecraft:map_color` など）からの値。地図の色との照合はまだ |
| 他プロジェクト（Third-party） | 他の Bedrock プロジェクトの値（出典とバージョンをメモに記録） |
| 推定（Estimated） | Java 版などからの推定値 |
| 不明（Unknown） | 使える値がない |

推定値を確認済みとして表示することはありません。陰影の倍率と段差は別々に状態を持ちます
（倍率は地形の地図からでも確認できますが、段差は高さが分かるテストパッドでしか確認できないため）。

## これまでに確認できたこと（Bedrock 1.21.132〜1.26.51）

[shading-rules.md](shading-rules.md) の「4. Bedrock での確認状況」を参照してください。要点:

- 陰影の倍率は Java 版と同じ 180 / 220 / 255 で、基本色から直接切り捨てて計算されていました（gd-codes の「通常色から丸める」方式は不一致）。
- 13 の色セットの基本色が Java 版と同じ値でした。
- 何もない列は黒で描かれます。水はバイオームの色になるようです。
- **段差の規則（1.26.51）:** ±1 は座標の偶奇で交互、±2 以上は常に。陰影テストパッド 8,032 点で、checker モデルが RGB まで 100% 一致しました。

## 検討したほかの方法

- **Script API**（`BlockMapColorComponent` の `color` / `tintedColor`、`Block.getMapColor()`）:
  `getMapColor()` はプレリリース（Beta API）で、Beta API を有効にしたワールドが必要です。
  基本色の取得には使えますが、陰影や最終的な地図の色は分からないため、地図を読み取る方法を優先しました。
- **ほかのプロジェクトのデータ**（bedrock-data、CloudburstMC/Data、bedrock-render など）: 地図の描画色が
  実測値かどうか・対象バージョンを確認してから「他プロジェクト」の状態で取り込む候補です（未使用）。
- 地図の保存形式は [Image Map](https://github.com/tryashtar/image-map) の Bedrock 対応（`map_<ID>` の NBT と
  `colors`）を参考にしています。コードは使っていません（BMAP の LevelDB 読み取りは独自実装です）。
