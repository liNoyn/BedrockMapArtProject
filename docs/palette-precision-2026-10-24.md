# 色数制限時の精度強化（第3段階）

この文書は第3段階の記録。現在のモデル別優先順位と追加候補は
[第4段階の検証](model-priority-2026-10-24.md)を参照。

第2段階の最終Coreを基準に、全17方式の色数制限と、主要3方式の256×256画像を調べた。
制限しない通常の変換に、今回の配色探索は適用しない。

## 変更内容

以前は使用回数の少ない色から段階的に削っていた。似た背景色と、少量の高コントラストな色を
区別できず、冗長な背景色を残して黒い輪郭を落とす場合がある。

新しい `PaletteReducer` は、制限前の各モデルの出力を「パレット項目×陰影」の重み付き分布にまとめる。
単に使用数を数える代わりに、他の色で置き換える誤差を選択中の色距離で評価し、
指定数まで色を加えた後、一色ずつの入れ替えでさらに改善する。初回に使わなかった色も候補にできる。
色分布を基準にするのは、元モデルが選んだ配色や混色を考慮するためであり、
元画像全画素に対する大域最適化ではない。計画用の行列は画素数ではなくパレットと陰影の数で決まる。
高さ制限や陰影ペナルティがある場合は、同じ陰影の代替色で計画する。

### 実際の出力で比較する

分布の置き換え誤差が減っても、ディザ後の画質が改善するとは限らなかった。
例えば2色制限のmixed/Flatでは、計画だけを採用するとKnollBayerの総合値が12.72→15.07と悪化した。
そこで従来の段階的な削減も実行し、提案と従来の両方を実際に変換する。

最終出力は、原画像に対する多尺度の総合誤差が、次の両方で悪化しない場合だけ提案へ切り替える。

- 選択されている色距離（RGB、Weighted RGB、Lab、Oklab、CIEDE2000）
- 既存の知覚的な評価に使うCIEDE2000

少なくとも一方が厳密に改善しなければ従来結果を保つ。同じパレットに到達した場合は変換結果を再利用する。
評価時には原画像の色変換・ぼかし・マスク処理を共有し、独立に4回測るより計算とメモリを抑えている。
高さ計画全体では探索される内部設定も変わり得るため、配置後の高さ・陰影も別途検証する。

この比較はPixel/Near/Farを重み付けした総合値に対するもの。全ての距離・画素が一律改善するという意味ではない。
またRGB/Lab/Oklabでは二乗距離、CIEDE2000ではΔEを使い、異なる色距離の値同士を直接比較しない。

## 48×48での測定

gradient、mixed、illustration、outline-aa、coffee、rare-outlineの6画像。
各モデルでFlatとValley高さ4の12条件、3回の変換時間の中央値を条件間で平均した。
rare-outlineは、近い明色2色と少量の暗色から作る追加の合成画像。

|2色制限|総合誤差 前→後|時間 前→後（ms）|
|---|---:|---:|
|イラスト|11.387279 → 10.169795|66.43 → 73.07|
|ブレンド|11.405516 → 9.900001|34.13 → 52.16|
|バランス|11.429446 → 9.945264|48.62 → 65.71|

|6色制限|総合誤差 前→後|時間 前→後（ms）|
|---|---:|---:|
|イラスト|5.866517 → 5.866517|64.42 → 74.77|
|ブレンド|5.642317 → 5.359015|38.54 → 54.49|
|バランス|5.926738 → 5.713335|51.34 → 64.58|

2色の主要方式では約11〜13%の誤差低減。6色でも改善する方式があるが、イラストのこの条件では
従来結果が選ばれた。追加の変換・比較を含めた最終設定は、速度向上としては扱っていない。
精度を優先する代わりに、色数制限中の処理時間が増える。
計画だけを採用した案は高速だったものの、個別画像の画質悪化があるため既定にはしていない。

## テストと成果物

最終設定の比較は444条件（48の2色204＋48の6色204＋256の6色36）。
全条件で、従来より総合誤差が増えたケース、色数超過、配置後の色不一致・地形依存・不安定ブロック・高さ超過は0。
6色制限の全17方式×高さ2/4/8/16×グリッド配置2通り×支持2通り×5画像、計1360条件も合格した。
こちらの行列は要求色数と実使用色数を各行に保存し、色数上限も同時に検査している。

全500テスト合格（Core 491＋GUI 9）。今回追加したテストは134件。
通常のReleaseビルドは警告0・エラー0。色数無制限の828枚（出力816＋原画像12）は前段階とSHA256一致。

256×256・6色制限（同じ6画像・各12条件）では次の結果だった。

|方式|総合誤差 前→後|時間 前→後（ms）|
|---|---:|---:|
|イラスト|6.232280 → 6.227658|919.71 → 1298.69|
|ブレンド|5.755903 → 5.611057|1153.63 → 1615.16|
|バランス|6.036850 → 5.909016|1238.76 → 1637.41|

この大きさでも改善するケースはあるが、比較の追加コストがある。
元から使う色が制限以内なら、配色探索と新旧比較を省略する。

`PaletteReductionTests` には、全17方式での希少な輪郭色の保持、透明画素の無影響、
1色の提案と全候補の全探索の一致、17方式×5色距離での従来結果との比較、
共有した画質評価処理と独立した評価の一致を追加した。
1色の提案が分布の目的関数で最良でも、最終結果は実出力の多尺度評価によって従来結果を選ぶことがある。
輪郭保持は他の色の代替コストとの兼ね合いであり、全画像で希少な色を必ず優先する保証ではない。

成果物は `artifacts/codex-reviews/2026-10-24-palettes/`。
比較基準のソースは前段階の `2026-10-24-mixing/final-source/`。
`candidate-source/` と `after48-*` は実出力比較を入れる前の提案、`final*` が採用設定。
`Verify.ps1` は同一条件の画質、使用色数、配置、色数無制限の出力、TRXを検査してJSONを生成する。

`comparison.png` は左が原画像、中央が従来、右が今回。上から48・2色のmixed/Flat/イラスト、
48・2色のcoffee/Valley高さ4/イラスト、256・6色のcoffee/Valley高さ4/ブレンド、
48・2色のrare-outline/Flat/イラスト。
最後の例では暗い線を失う従来結果が残っており、輪郭の取りこぼしを全て解決したという証拠にはしていない。
選択中の色距離だけから作った一案では、別の基準で作る良い候補を拾いきれない可能性が残る。
今後は候補の多様化と実出力での比較を組み合わせて詰める必要がある。
