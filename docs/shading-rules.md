# 地図の陰影規則と BMAP の 3D 処理

BMAP が 3D マップアート（階段）で前提にしている規則と、それをどう検証しているかをまとめます。
統合版での実機確認はまだ済んでいません（最後の「確認方法」を参照）。

## 1. 規則

縮尺 0 の地図の 1 ピクセルは、その列（x, z）で **一番上にあるブロック** の地図色を表示します。
色の明るさ（陰影）は、**真北（z − 1）の列の一番上のブロック** と高さを比べるだけで決まります。

| 北隣と比べた高さ | 陰影 | 倍率（Java 版の値） |
|---|---|---|
| 高い | 明 | 255 / 255 |
| 同じ | 通常 | 220 / 255 |
| 低い | 暗 | 180 / 255 |

- **差の大きさは関係ありません。** 1 段でも 10 段でも高ければ「明」です。
  そのため「暗」は何段でも一気に下げられ、Valley 階段はこれを使って低く抑えます。
- **東西の隣は関係ありません。** 列（x）ごとに完全に独立しています。
- 地図の 1 行目は、地図の範囲のすぐ北の行（支え行）と比べます。BMAP は必ず支え行（z = 0）を出力します。
- 北隣の列が空（透明ピクセル）の場合、そこに見えるのは建築の下の地形です。陰影は地形の高さで決まり、予測できません。
- 支えブロックがその列の見えるブロックより上に出ると、それが「一番上」になって地図の色が変わります。
- 砂・砂利・コンクリートパウダーは下が空だと落下し、カーペット・感圧板は壊れます。どちらも地図が変わります。
- 135 / 255 の 4 段目の明るさは建築では出せません（地図データを直接書いた場合だけ）。

## 2. BMAP での扱い

### 地図シミュレーター（`Shading/MapShading.cs`）

ブロックの配置（見えるブロック・支え行・支えブロックすべて）**だけ** から、上の規則で地図を描き直します。
減色の段階で計画した色とは独立に計算するので、両者を比べると「減色 → 高さ → 支えブロック」の流れ全体を検証できます。

`ShadingAnalyzer` は次を報告します。

- 計画した色と違うピクセル（**常に 0 であるべき**。テストで全方式・全支えモードを確認）
- 北隣が空で地形しだいのピクセル
- 落下・破損するブロック
- 暗・通常・明のピクセル数、最も高い列、平均の高さ、段差と 2 段以上の落差の数、列ごとの高さ分布

### 見つかった不具合

シミュレーターで、Valley 階段と「すべて（サバイバル向け・最適化）」の組み合わせで
**支えブロックが隣の低い列の見えるブロックより上に置かれ、地図に写ってしまう** 問題が見つかりました
（128×128 の例で 13〜40 ピクセル）。支えブロックは必ずその列の見えるブロックより下に置くよう修正し、
回帰テストを追加しています。

### 高さの上限

上限を決めた場合、列ごとの必要な高さは「明（または暗）の連続の長さ」で決まります（通常は連続を切らず、
逆の陰影で切れます）。BMAP はこの連続の長さを状態にした動的計画法（Viterbi）で、上限内で色差が最小になる陰影を
列ごとに求めます（ディザなし・規則ディザでは最適解）。

- Classic 階段は常に 1 段ずつ上下する（一気に下げない）ため、高さは全段差の累計になり、連続の長さでは抑えられません。上限は Valley 専用です。
- 誤差拡散ディザでは、連続が上限に達したところで止め、その色の誤差を周囲に拡散します。
  「先に Viterbi で陰影を計画し、その中でディザし直す」方式も試しましたが、
  見た目の色差は全ての上限で悪化しました（例: 上限 4 で ΔE 3.44 → 3.59）。そのため採用していません。

### 3D ビュー（`Preview/Viewer3D.cs`）

- 面ごとの陰影は地図シミュレーターと同じ規則で計算します（「地図に写る色」表示を真上から見ると予測地図と一致することをテストで確認）。
- 「陰影」表示: 暗 = 青、通常 = 灰、明 = 黄。予定と違う色は赤、地形しだいは紫、落下・破損は橙。
- アンビエントオクルージョン（Minecraft のスムースライティングと同じ 4 隅の判定）と、太陽方向への影。
- チャンク（16）と地図（128）の境界線、表示する高さの上限（1 段ずつ建てるとき用）、最も高い列への移動。
- 遠近法では透視補正したテクスチャ座標で描画します。

## 3. 確認方法（陰影テストパッド）

ワールドデータを読み書きせずに、統合版の陰影規則を確かめるための機能です。

1. マップ設定の「陰影テストパッドを出力」で、地図 1 枚分（128×128）の `.mcstructure` と
   `predicted_map.png`（BMAP が予測した地図）、`説明.txt` を出力します。
2. パッドには 1 段・3 段の上り、1 段・5 段の下り、上り / 下りの階段、ジグザグ、東西の高さ違いが並び、
   それぞれ通常のブロック・カーペット・ハーフブロックで作られています。
3. ゲーム内で地図の範囲に合わせて読み込み、地図を作って `predicted_map.png` と見比べます。
   一致すれば、統合版も同じ規則であることが確認できます。違う場合は Issue でお知らせください。
