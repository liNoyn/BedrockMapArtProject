# Bedrock の地図色・陰影: 外部実装の検証結果

研究資料「Minecraft Bedrock Edition — 地図色・陰影計算 総合研究資料 v1.0」（2026-10-18）で挙げられた外部実装を、
**Bedrock 自身が描いた地図の RGBA** を基準に検証した結果です。外部実装は仮説として扱い、そのまま正解とはしていません。

使ったデータ: Bedrock 1.21.132〜1.26.51 が描いた地図 12 枚（約 19 万ピクセル）。ワールドのデータベースの一時コピーから
読み取りました（`BMAP.Cli mapcheck`・`refcompare`）。画像マップ（ゲームが描いたものではない地図）は除外しています。

## 1. 陰影の倍率と丸め方

| 仮説 | 出典 | 結果 |
|---|---|---|
| 基本色 × 180・220・255 / 255 を切り捨て | Java 版、Nukkit `colorizeMapColor`、ConcreteMC/Alex | **一致**（13 色セットで 2〜3 段階すべてが完全一致） |
| 通常色から 暗 = ⌊通常 × 180/220⌋、明 = ⌈通常 × 255/220⌉ | gd-codes `darkPixel` / `lightPixel` | **不一致**。明・暗 3,577 ピクセルのうち、Java 式だけで説明できるものが 112、gd-codes 式だけで説明できるものは 0 |
| 平らな場所 = 基本色そのまま、段差に応じて段階的に変化 | PowerNukkitX `getMapColorAt` | **不一致**。ピクセルの 52% が「基本色 × 220/255」ちょうどで、このモデルではこの値はほぼ出ません |
| 135/255（4 段階目） | Java のデータ、Alex | 1 ピクセルも見つかりませんでした（建築では出ないと考えられます） |

## 2. 陰影が変わる段差

| 仮説 | 出典 | 状況 |
|---|---|---|
| 段差 1（明暗が対称） | Java 版 | 未確定 |
| 段差 2 | gd-codes `findYMap`（建築は常に ±2）、Nukkit（`Δy × 4 / 5` を **整数除算**: ±1 は 0 になる） | 未確定。3 つの独立した情報源（gd-codes・Nukkit・2023 年のユーザー報告）がこちらを示しています |
| 明暗で段差が違う（非対称） | 研究資料の提案 | 測定時に明・暗を別々に推定し、別々に保存します |
| 段差 1 が座標の偶奇で交互になる（チェッカー） | Java 式の偶奇の項 | 下記のとおり、**浮動小数点では効きません**。厳密計算した場合の仮説として残しています |
| 段差の大きさで段階的に変わる | PowerNukkitX | 倍率の結果（1 章）と矛盾 |

地形の地図からは高さが分からないため、段差は **陰影テストパッド** でしか判定できません。BMAP は測定結果を
すべての候補モデルと照らし合わせ、パッド後半（帯 5〜8）を検証用に残したうえで、最も一致したモデルを選びます。
それまでは「マップ設定 → 3D → 陰影モデル」で候補を選んで生成できます。

### 偶奇の補正について

Java の式 `d = Δy·4/5 + ((x+z)&1 − 0.5)·0.4`（`d > 0.6` で明）を倍精度で計算すると、
`0.8 − 0.2 = 0.6000000000000001` となり、`0.6` を超えます。つまり段差 1 でも全ピクセルが明になり、
偶奇の項は結果を変えません。段差 1 の階段が Java で正しく働くのはこのためです。Nukkit は同じ式を整数除算で計算するため、
±1 が 0 になり、実質的に「段差 2」になります。

## 3. 地図色（gd-codes の 82 カテゴリとの照合）

`BMAP.Cli refcompare` は gd-codes の `data.js` を実行時にダウンロードして照合します（BMAP には同梱しません）。

- 82 カテゴリ中 **57 が BMAP（Java 値）と完全に同じ** 通常色でした。
- 違ったもの:

| カテゴリ | gd-codes | BMAP（Java 値） | 判断 |
|---|---|---|---|
| 紫 | #844DB0 | #6D3699 | **gd-codes に変更**。実際の地図に #844DB0 が 3 ピクセルあり、Java 値は 0 |
| ネザー | #600000 | #600100 | gd-codes に変更（他プロジェクト） |
| ラピス | #406EDC | #3F6EDC | gd-codes に変更（他プロジェクト） |
| 真紅のナイリウム | #A32A2A | #A3292A | gd-codes に変更（他プロジェクト） |
| シラカバの葉 | #3B4D27 | #006A00（葉） | 独立した色セットに（他プロジェクト） |
| トウヒの葉 | #2D472D | #006A00（葉） | 独立した色セットに（他プロジェクト） |
| スカルク | #0B0F13 | #151515（黒） | 独立した色セットに（他プロジェクト） |

- 羊毛ハーフブロック 16 色（`*_wool_slab` / `*_wool_double_slab`。Bedrock 1.26.50 の公式メタデータに存在）は、
  gd-codes では羊毛と違う色になっています。**新しい色セット 16 個** として追加しました（他プロジェクト・未検証のため既定では選びません）。
- 優先順位は「Bedrock の地図で確認済み ＞ gd-codes（Bedrock での実験値） ＞ Java の値（別エディション）」です。
  元の Java 値は色プロファイルのメモに残しています。

## 4. まだ分からないこと

- 陰影が変わる段差（1 か 2 か、明暗で違うか）: 陰影テストパッドで測定できます。
- 何もない列は黒（#000000・不透明）で描かれるようです（約 8.7 万ピクセル）。
- 水は #1E5AF5・#0853C5 など、Java の水の地図色と一致しません（バイオームの水の色が関係していると考えられます）。BMAP は水を扱いません。
- 色テストパッドでブロックごとの色を測るまで、ブロックと色セットの対応は推定です。
